# PHREAK

**PHREAK, by [dag](https://dagnazty.dev/): [SLOOP](https://github.com/isod89/sloop-fm1) 2.8.4 for the M-VAVE FM-1, with three drum tracks, samples from a USB stick that you can shape like a synth, eight song sections, and more trap sounds.**

Everything in SLOOP works as before: the four tracks, song mode, punch-in FX, MIDI, USB audio, the web editor. The boot screen and ABOUT say PHREAK and its number (1.9) and *by dag*; the version string the web editor reads stays `SLOOP 2.8.4+`.

## What it adds to SLOOP

| | |
|---|---|
| **LOAD FROM USB** (hold **OCT+** while switching on, [usbstick.c](firmware/src/usbstick.c)) | Samples from a USB stick into the user sample slots USR1–USR6. Browse the folders of a FAT32 stick, starting in `SAMPLES/` (or the stick's top level when it has none), at any depth; any folder with WAVs in it can go into a slot: its WAV files (8/16/24/32-bit PCM, mono or stereo, any rate) are mixed to mono, converted to 22050 Hz IMA ADPCM and written to the slot, up to 16 files and about 7 s. When they're too long, the longest are shortened (with a fade) until all fit. One file plays over the whole keyboard; when every file name has a note (`PAD C3.wav`) they split the keyboard between their notes; otherwise they go to the drum lanes in order (KICK, KICK 2, SNARE, CLAP, HAT…), so the folder plays as a USR kit. KNOB picks a line, OCT+ opens a folder or loads (a folder with WAVs lists *LOAD … > USR1* to *USR6* first), OCT− goes back up. **(1.2) One file alone:** the folder's WAV files are listed too (indented, the first 32 by name); OCT+ on one, then *LOAD THIS > USR1* to *USR6*, loads it alone across the whole keyboard (its note from its name, else C4): a sample for a synth or bass track (a SAMPLE sound from PRESETS, then EDIT → SET, KNOB 1: USR1–6). **(1.3) PLAY** on a highlighted file (or its slot list) plays it through the FM-1's output, streamed from the stick (the first half second read before it sounds, up to 30 s); any button or knob stops it. **(1.7)** The MASTER knob sets its level (`us_pv_gain`: the ADC read every ~40 ms, smoothed, through play's curve `master_q12 = k10² / 256`, glided across each audio half). At full it is the same level as before. The ADC is set up there first, because LOAD FROM USB runs before `fm1_main`. Switch off to leave. |
| **Sample editor** (PHREAK 1.5, [smpedit.c](firmware/src/smpedit.c), [smpedit_save.c](firmware/src/smpedit_save.c)) | **LFO** held 0.7 s (`btn_hold`, as HOME's menu) opens it; a tap still opens the LFO pages. It edits a user slot's zones in RAM (`se_z`, 16 zones, in `.pool` with the waveform's min / max a column), positions as shown (after REVERSE), and changes nothing in flash before **SAVE**. PRESETS the slot, ALGORITHM the zone, LFO tap / OCT the page: **TRIM** (START, END, fade in / out in ms), **LOOP** (MODE OFF / LOOP / HELD = `SMP_LOOP_HELD`, L.START, L.END), **KEYS** (ROOT, LOW, HIGH), **FX** (REVERSE, NORMALIZE). **SAVE** (the song stopped) rebuilds the slot in the delay line's RAM (`dly_buf`, 128 KB) with the audio interrupt masked (`fm1_irq_unmask`, new in [fm1_irq.h](firmware/hal/fm1_irq.h)). A zone with only LOOP / KEYS changes keeps its ADPCM bytes; its loop state (`pred`, `idx`) is found by decoding to L.START. Any other zone is decoded, trimmed, reversed (decoder checkpoints every 256 samples, decoded in blocks backwards), normalized to a 30000 peak, faded, and encoded again from 0 / 0 (as [usbstick.c](firmware/src/usbstick.c)), its loop state taken from the encoder. Then the header's CRC, only the sectors needed are erased and written, the delay line is cleared, and the slot is scanned again. **PLAY (1.6)** builds the current zone the same way (`se_build_zone`) into the delay line without writing flash; [smpedit_pv.c](firmware/src/smpedit_pv.c), included by [fx.c](firmware/src/fx.c), plays it after the metronome click at the zone's rate (linear interpolation), looping as SAMPLE does (HELD while PLAY is held), with a playhead on the screen. While the editor holds the line (`se_dly_off`) the tempo delay neither reads nor writes it; when the preview stops or ends, the line is cleared and handed back. Tests: [smpedit_test.c](tests/smpedit_test.c) (each edit on a RAM slot, the bytes kept for LOOP / KEYS, the CRC, the interrupt off around the stage, the line cleared after, refused while playing) and [ui_pages_test.c](tests/ui_pages_test.c) (LFO held opens it on the track's slot, pages, HOME leaves, the LFO tap as before; renders `smpedit-*.ppm`). |
| **Resampling** (PHREAK 1.8, [resample.c](firmware/src/resample.c), the RESAMPLE page in [smpedit.c](firmware/src/smpedit.c), `rs_write` in [smpedit_save.c](firmware/src/smpedit_save.c)) | The sample editor's fifth page: RATE (22050 Hz, two samples averaged, or 44100), BARS (FREE, 1, 2, 4, 8: `rs_bar_frames` = bars × 4 × `BEAT_U` / BPM source frames; a length the take can't hold at this tempo is skipped and refused at arm), START (PLAY: the first block of a bar, `clk_beat % 4 == 0`, `clk_pos` inside the block, with the transport running; NOW; NOTE: the first sample at or over 330, about −40 dB) and SOURCE (MIX: after DUST, punch-in FX and the DJ filter, before MASTER, as USB AUDIO = FULL; DRY: before the wet buses are added). REC arms (over a sample or edits: a second time); the editor closes. The audio side (`rs_block_begin` before a block's events, `rs_tap` at both taps in `mix_block`) mixes left and right to mono through `knee` and encodes IMA ADPCM from 0 / 0 a sample at a time into the lower 64 KiB of `dly_buf` (131072 samples: 5.94 s at 22 kHz, 2.97 s at 44 kHz). Meanwhile the tempo delay runs on the upper half (`rs_dly_half`: base 32768, mask 32767, `delay_samples` clamped to 0.74 s), so the delay and the punch-in FX are in the take; the line is cleared when it changes hands. The metronome click is left out while recording (and while NOTE waits). The take ends at its bars, full, on an LFO tap (`stop_req`, at the next block) or, START PLAY, when the transport stops; LFO held drops it. With the transport stopped the main loop (`rs_poll`, from `ui_input`) writes it: the audio interrupt masked, a header (one zone, `RESAMPLE`, root C4, keys 0–127, rate Q16 1/2 or 1, one-shot, CRC), only the sectors needed erased, header and data written straight from the line, the line cleared and whole again, the slot scanned, the editor opened on it. Autosave and the section flush wait while a take is on (an erase would be a gap in it). A red banner over whichever screen shows (`rs_banner`, after `ui_draw_page`) gives the slot, the state, the seconds and a peak meter. The editor's times and fades now use each zone's own rate (`se_hz_of`), so a 44 kHz zone shows its real length. Tests: [resample_test.c](tests/resample_test.c) (NOW / NOTE / PLAY starts, BARS, FREE until full, the LFO and transport stops, 22 and 44 kHz pitch and level, DRY / MIX, the delay writing only its half, a held A4 through `mix_block` into a take, the write: one zone that reads back sample for sample, only its slot erased, the interrupt off, the line cleared) and [ui_pages_test.c](tests/ui_pages_test.c) (the page, REC twice over a sample, armed state and banner, LFO held drops it and doesn't open the editor, waits for the transport, written when stopped; renders `smpedit-resample.ppm`, `resample-*.ppm`). |
| **USR sounds in PRESETS** (PHREAK 1.9, [tools/gen_samples.py](tools/gen_samples.py) `USER_PRESET`, [ui.c](firmware/src/ui.c) `BANK`, [ui_draw.c](firmware/src/ui_draw.c) `graph_browse`) | Six SAMPLE presets USR1–USR6 generated with SET = `SMP_USR0 + k` (8..13), full sustain, release 40, a little delay and reverb; the BANK gets a kind `USR` with them last (Program Change numbers of the factory sounds unchanged; the list wraps, so they are one turn left of the first sound). The browser shows `USRn` as the tag and the slot header's 8-character name, or EMPTY when `usr_nz[k]` is 0. Test: [ui_pages_test.c](tests/ui_pages_test.c) (each loads SAMPLE on its slot, listed as USR, USR6 left of the first sound). |
| **Live sampling** (PHREAK 1.9, the Samples page of [web/editor.html](web/editor.html), `REC`, `recOpen` … `recAdd`) | Step 2's third mode, *Record live*. `getUserMedia` on the chosen input (echo cancellation, noise suppression and auto gain off; the FM-1's USB audio found by its name and picked first), a `ScriptProcessor` mixing to mono at the context's rate, no output (no feedback). *Start on sound*: a −40 dBFS gate with 10 ms of pre-roll from the last block. The take is capped at what the slot's list has left (`recRoom`, 22050 Hz, 4 bits a sample) and 60 s. Trim (Start / End), resampled to 22050 Hz with the editor's own `resample`, normalized to a 30000 peak or kept as recorded, then added to the files draft as `REC n.wav` / `RESAMPLE n.wav` at root C4 and sent by the existing upload (SMP_BEGIN / WRITE / END). Strings in English and Japanese; colours from the page's tokens. Checked with the mock FM-1: a take trimmed and uploaded into USR1. |
| **Edit before sending, longer samples** (PHREAK 1.9, [web/editor.html](web/editor.html): `fileEditor`, `fileRender`, `fitRates`, `atRate`, `buildSlot`) | Each file in the Samples draft keeps its decoded original (`orig`, 22050 Hz) and its edits (`ed`: start, end, fades in ms, pitch in semitones by resampling as a tape, reverse, normalize to 30000); `fileRender` makes `s` again from them on each change, and the loop points are clamped into it. A file also has a `rate` (22050, 16000, 11025, 8000): `buildSlot` low-passes it (63-tap Blackman windowed sinc at 0.45 of the new rate), resamples it, scales its loop points and writes the zone's rate field (rate / 44100, Q16: the firmware already plays any rate). `fileBytes` / `draftBytes` count at each file's rate; `fitRates` lowers the longest file one step at a time until the list fits (on adding files and recordings, and the *Fit to the slot* button). The preview (`filePreview`) plays the file at its rate. Tests: [test_web.mjs](web/test_web.mjs) `samplesRates` (the header's rate and size, loop points scaled, 7 kHz removed and 1 kHz kept at 8 kHz, a 10 s file fitted to 11 kHz, the longer of two lowered first, trim, pitch +12 halves the length, fades, reverse). |
| **Sections A–H** | The song has eight sections instead of four. **SAVE + keys 1–4** play A–D and **SAVE + keys 9–12** play E–H (chains mix them freely); **SAVE + keys 5–8** store into A–D, or into E–H after **SAVE + key 15** switches them over (the tiles say which). SAVE → SECTION lists all eight in two columns, the SONG screen picks any of them, and the web editor's sections, Song, LIVE, backup and song-file pages carry E–H (INFO ends with the section count, 8; backup objects 12–15; LIVE op 13). E–H are saved in five flash sectors the four of them share: 0x93000–0x96FFF, above the app area an update writes, and 0xFB000; a save always goes to a sector that holds no section's current copy, so a power cut while saving keeps the previous one, as A–D's two-sector pairs do. |
| **Drum tracks D2, D3** ([xdrums.c](firmware/src/xdrums.c)) | Two more drum tracks next to the drum track (D1). **ALGORITHM** turns through tracks 1, 2, 3, then **D1, D2, D3** (*DRUM TRACK D2*; the TRACKS strip and the DRUMS screen say *d2* / *d3*). The one you pick is the drum track for everything: the DRUMS screen, the keys, REC, step entry, the kit (PRESETS), its LENGTH, DIV and swing, MUTE, PAN and LEVEL (D1's LEVEL is GLO > DRUMS LEVEL as ever; D2 and D3 have their own). All three play together, on the drum track's 6 voices (the oldest hit gives way, the kick last), through its INSERT, filter and sends. At power-on (and after NEW) D2 is on the **USR1** kit and D3 on **USR2**, empty: load a folder of drums into USR1 / USR2 (LOAD FROM USB) and program them. They're kept with the working project and with every section A–H (two sections to a flash object, in the last 12 KiB of each user sample slot), and they follow song mode. While another one is shown, a drum track plays its hits, levels, ratchets, nudges and fill conditions; it sends no MIDI, and only D1 has parameter locks. The web editor sees the drum track shown, and its backups hold D1 only. |
| **USR kit sound** (PHREAK 1.1) | When a drum track's kit is **USR1–USR6** or **USR3+4**, the **ENV**, **LFO** and **EDIT** pages open on it (with any other kit they still say *DRUM TRACK*), and shape every hit as the SAMPLE engine shapes a note. **ENV**: ATK DEC SUS REL; each hit holds for the step's **GATE** (SEQ → PATTERN, a share of a step at the track's DIV), then its release. **ENV DEST**: FLT (the envelope opens the filter), PIT (a pitch drop at the start). **LFO / LFO 2 / LFO DEST**: RATE WAVE PHASE FADE, SYNC TRIG POL, to PIT (vibrato), FLT (wobble), AMP (tremolo). **EDIT 1 (SAMPLE)**: KIT, **TUNE** ±24 semitones, **BITS**, **LOOP** (the sample again from its start while the hit holds: a short sample as a pad). **EDIT 2 (TONE)**: **CUT**, **RES**, **DRV**. **FILTER**: TYPE LP / BP / HP, CUT, RES (ANALOG's resonant filter). D1, D2 and D3 each have their own, kept with the project and with each section. At their defaults (no attack, SUS and REL full, CUT open, nothing else) a hit plays exactly as before, and costs nothing more; projects from before open that way. The values sit in drum-track slots a drum track never used (the VOICE page's: [drums.c](firmware/src/drums.c) `DS_*`), so the project format is unchanged. |
| **Trap** | Four more 808 basses on ANALOG in the BASS group (808 LONG, 808 PUNCH, 808 GRIT, 808 GLIDE), and three drum kits after JAZZ: **RAGE**, **PLUGG** and **MEMPHIS**. |

## Build and install

The same as SLOOP (see [BUILDING.md](BUILDING.md)):

```
sh build.sh --release 1.9          # build/phreak-1.9.fwsc, identity FM-1_919
sh tests/run_tests.sh              # SLOOP's host and web tests, with these additions
python3 tools/fm1_install.py build/phreak-1.9.fwsc
```

The JieLi clang sometimes segfaults under Docker on Apple silicon. Run the build again and it goes through.

## Notes

- **Tests:** all of SLOOP's host and web tests pass. The exception is *target cost of the render loops*, which fails identically on plain SLOOP 2.8.4 because its budget file is out of date upstream.
- **Tests:** [usrsound_test.c](tests/usrsound_test.c) shapes USR kit hits with each control, checks the defaults change nothing, and saves and loads them with projects and sections (and PHREAK 1.0's sections).
- **Tests:** [xdrums_test.c](tests/xdrums_test.c) plays D2 and D3 while D1 is shown, mutes one, swaps them while playing, and saves and loads them with a section.
- **Kit positions:** RAGE, PLUGG and MEMPHIS come after JAZZ, so SLOOP's factory kits keep their numbers, but the user kits (USR1–4, SYN1–4) each move up three compared to SLOOP.
- **LOAD FROM USB, the hardware:** the FM-1 can't power a stick, and a stick (or a hub) only shows up when it sees 5 V from the host. Use a USB-C OTG adapter with a charging port (USB-C plug, USB-A socket, USB-C power in) and a phone charger in it: the charger powers the stick and charges the FM-1. A plain OTG adapter, or a hub whose power only feeds its own ports, shows *PLUG IN A USB STICK*. Sticks over 32 GB usually come as exFAT: format them as FAT32. The FM-1's USB to the computer is off on this screen. The USB host mode follows JieLi's AC79 SDK (its `usb_h_sie_init`, `usb_h_chirp_and_reset` and transfer code, USB0 branches; the register helpers are in [fm1_usb.h](firmware/hal/fm1_usb.h)). Tests: [usbstick_test.c](tests/usbstick_test.c) runs the FAT32, WAV and slot code on a disk image, [usbstick_check.py](tests/usbstick_check.py) decodes the slots it wrote.
- **Sample slots, smaller:** each user slot holds 68 KiB now (about 6.3 s; 80 KiB, about 7.4 s, up to SLOOP 2.8.4): the last 12 KiB of each keep D2 and D3. A slot loaded before with more than 68 KiB of samples reads as empty: load it again (LOAD FROM USB, the web editor). USR3+4 holds about 12.5 s.
- **USR5, USR6 (1.4), and the app area:** only PIANO and BASS are built in ([gen_samples.py](tools/gen_samples.py) `BUILT_IN`). That frees 175 KB of the app image (388 KB now), so the app area ends at **0x71000** instead of 0x93000: `app.bin` is 0x6C800 bytes ([fm1pkg_make.py](tools/fm1pkg_make.py) `APP_SLOT`, `FLASH_SIZE` 0x71000; [app.ld](firmware/app.ld)). The update loader writes only [0x4000, 0x71000) ([ldr_core.c](firmware/loader/ldr_core.c) `LDR_APP_HI`, and its write window in [loader.c](firmware/loader/loader.c)). USR5 and USR6 are 68 KiB each at 0x71000 and 0x82000 ([eng_sample.c](firmware/src/eng_sample.c) `SMP_USER_OFF`), in the store's write window ([fm1_flash.h](firmware/hal/fm1_flash.h) `FL_USR5_*`) and in the plain (unencrypted) XIP window, which now starts at 0x71000. **SET numbers:** USR1 stays at 8 (`SMP_USR0`), where it was when there were eight sets, so projects and presets keep their numbers. 2–7 play PIANO (`smp_src`), the SET / SRC knob skips them (`smp_set_step`), and the web editor hides their repeated name. **Drum kits:** 0–4 (the GM sample kits) clamp to the 808 (`drum_kit_ok`) and say 808; USR5 and USR6 are kits after SYN4 (`DRUM_USR5`). **Editor:** `SMP_INFO` reports 6 slots; backup objects 36 and 37 are USR5 and USR6 (a restore skips them on a FM-1 with fewer slots). [ldr_test.c](tests/ldr_test.c) checks that an update leaves 0x71000–0x92FFF alone, and [userkit_test.c](tests/userkit_test.c) checks the map and the set numbers.
- **After a crash:** A–D live in RAM that survives a reset; E–H and every section's D2 and D3 don't (that RAM is full). What you store while playing is lost only if the FM-1 crashes in the seconds before it's written to flash after you stop.
